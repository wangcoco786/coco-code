Glory Wisdom 三大业务板块与 7 大核心场景

模块一：美国海外仓标准出入库（GW-RC 仓，纯 WMS 作业）
· 场景 1：标准采购入库 (PO Inbound)

指令下达：AX → EDI (解析 850) → OMS → WMS (生成 RN 入库预报单)。

物理操作：美国仓收货，录入双单位（面积/重量），扫描序列号。

回传闭环：WMS (回传 RC) → OMS → EDI (汇聚数据) → AX。

（注：如果是库存增加，后续会体现在 EDI 846 的盘点对账中）

· 场景 2：标准销售出库 (SO Outbound - Retailer)

指令下达：AX → EDI (解析 850) → OMS → WMS (生成 DN 出库单)。

物理操作：拣配、打包、打印专属标签（如 Costco 的 UCC 标签）、绑定快递跟踪号（Tracking No）。

回传闭环 (高危点)：WMS (回传 DC 发货明细) → OMS → EDI (生成极为严格的 856 ASN) → AX。

只要 WMS 漏掉重量或包裹号，856 就会在 EDI 这一层被拦截，发不到 AX。

模块二：工厂直发业务（两段式履约与中转）
· 场景 3：工厂直发零售商 (Direct to Retailer)

指令下达：AX → EDI (解析 850) → OMS → Vendor Portal。

物理操作：工厂打包，在 Vendor Portal 登记物流并发货。

回传闭环：Vendor Portal → OMS → EDI (生成 856 ASN) → AX 及其终端零售商。

· 场景 4：工厂直发美国仓 (Direct to Facility —— 最复杂的两段接力)

指令下达：AX → EDI (解析 850) → OMS → Vendor Portal。

段落一 (第一层拦截)：工厂在 Vendor Portal 点发货。发货信息传给 OMS，OMS 在这里执行硬拦截，绝对不允许把状态推给 EDI 生成 856，因为货还在海上。

段落二 (内部转换与最终回传)：OMS 自动生成内部指令下发给 WMS (RN)。一个月后，货到美国，WMS 收货完毕 (回传 RC) → OMS 解除拦截 → EDI (发送入库确认/对应报文) → AX。

 
· 场景 5：纯工厂间调拨 (Tariff Evasion)

流转：此流程多为内部指令流转，AX 下达内部调拨令 → EDI (解析 850 或其他对应报文) → OMS → 两个 Vendor Portal 之间进行库存转移登记。

模块三：异常与逆向流程（系统断层区）
· 场景 6：分批发运与短装 (Partial & Short Shipment)

断点分析：不管是 WMS 还是 Vendor Portal 发生短装，实际执行信息推给 OMS 后，OMS 需要通过 EDI 856 向 AX 汇报。但如果发货数量与 AX 下达的 EDI 850 不一致，且没有提前协商好容差范围，856 极易产生财务争议或被系统拒收。

· 场景 7：订单变更与取消 (Cancellation/Alteration) —— 核心痛点

正规链路（目前缺失）：AX 发起变更 → EDI (发送 860 变更报文) → OMS → 阻止/修改 WMS 作业。

实际惨状：因为 EDI 860 没通，AX 无法通过系统下达"取消"指令。

变成人工发邮件 → 仓库在 WMS 手动点"Cancel"物理阻断 → WMS 把状态抛给 OMS → (由于缺乏顺畅的 EDI 逆向通知报文) OMS 无法通过系统闭环告诉 AX，只能再次依靠人工对账，或者靠定期的 EDI 846 (库存报表) 让 AX 发现库存没扣减。

EDI 报文类型速查：
850 - 采购订单856 - ASN发货通知
846 - 库存报表860 - 订单变更
关键风险点汇总：
  • 场景2：WMS数据缺失导致856被拦截
  • 场景4：两段式履约需严格管控拦截时点
  • 场景6：短装容差未协商导致财务争议
  • 场景7：EDI 860未打通，变更依赖人工
